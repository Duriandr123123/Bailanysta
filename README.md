# Bailanysta

Bailanysta — социальная сеть для школьных сообществ. Школы публикуют новости, фотографии и достижения, ученики ведут личные профили, а учителя собирают свои классы в закрытых чатах.

**Работающее приложение:** https://bailanysta-community.daniyarik74.chatgpt.site

**Публичный репозиторий:** https://github.com/Duriandr123123/Bailanysta

## Что реализовано

- Общая публичная лента, поиск по словам и хэштегам без учёта регистра, фильтр достижений, постраничная загрузка.
- Вход через ChatGPT; при первом входе создаётся профиль с постоянным публичным ID вида `BL-…`. Имя и описание редактируются.
- Создание школы, публичная страница, город, описание и редактирование информации администратором.
- Публикации от личного профиля и от школы. Новости, фотографии и достижения/грамоты; редактирование и удаление собственных постов.
- Назначение учителей администратором школы. Учитель создаёт собственные классы и добавляет учеников по ID.
- Закрытый общий чат школы и отдельные чаты классов. Сообщения сохраняются на сервере.
- Лайки, комментарии, уведомления о добавлении в класс/школу, назначении роли и комментариях.
- Светлая и тёмная темы с сохранением предпочтения; адаптивная вёрстка, состояния загрузки, пустых данных и ошибок.
- Собственный HTTP API, D1/SQLite для данных и R2 для изображений. Браузер обращается только к API своего приложения.

AI-генерация отложена по согласованному объёму. Для работы приложения API-ключ AI не нужен.

## Быстрый запуск

Нужны **Node.js 22.13+** и npm. Проверено с Node.js 22.22.3 на Windows. Из корня этого репозитория:

```bash
npm ci
npm run db:migrate
npm run dev
```

Откройте **http://localhost:5173**. Нажмите «Войти с ChatGPT»: в локальном режиме используется тестовый профиль Seedy без внешней авторизации. Это только локальная имитация для разработки, в опубликованном приложении действует настоящий вход ChatGPT.

При первом открытии автоматически добавляется вымышленный лицей «Орбита» и несколько демонстрационных публикаций. Это не реальные школа и ученики. Демоданные не перезаписывают пользовательские записи.

`npm run db:migrate` применяет только ещё не применённые миграции. Локальная база и файлы находятся в игнорируемой `.wrangler/state` и сохраняются после перезапуска. Не удаляйте эту папку, если хотите сохранить локальные данные.

### Сборка и проверки

```bash
npm run typecheck
npm run build
npm start -- --port 8787
```

В другом терминале:

```bash
npm run test:api
```

Интеграционный тест предназначен **только для localhost** и создаёт вымышленных тестовых участников и школы. Он проверяет API готового Worker и моделирует доверенные заголовки шлюза, чтобы проверять пять разных ролей. `npm start` не имитирует браузерный вход — для ручной проверки входа используйте `npm run dev`.

На Windows остановите `npm start` перед повторной сборкой: открытый Worker может удерживать каталог `dist`. Если системный npm повреждён и сообщает, что не найден `npm-cli.js`, исправьте установку Node/npm; обход для стандартного пути Windows: `node "C:/Program Files/nodejs/node_modules/npm/bin/npm-cli.js" run dev`.

## Сценарий знакомства

1. Войдите, откройте «Мой профиль» и укажите имя. Скопируйте публичный ID.
2. В разделе «Школы» создайте свою школу — вы станете её администратором.
3. В «Управлении» добавьте по ID другого зарегистрированного пользователя с ролью «Учитель».
4. Учитель открывает школу, создаёт класс и через «Участники» добавляет ученика по его ID.
5. У ученика появляются общий чат школы и чат его класса. Остальные классы ему недоступны.
6. Опубликуйте школьную новость или достижение, прикрепите фото, поставьте лайк и оставьте комментарий.

Для демонстрации нескольких реальных участников нужны разные аккаунты ChatGPT. Локальный браузерный mock выдаёт один тестовый аккаунт; многопользовательские права проверяются отдельным API-тестом.

## Права доступа

| Действие                               | Администратор школы     | Учитель школы                 | Ученик               | Гость |
| -------------------------------------- | ----------------------- | ----------------------------- | -------------------- | ----- |
| Читать публичную ленту и профили       | Да                      | Да                            | Да                   | Да    |
| Создать личный пост, лайк, комментарий | Да                      | Да                            | Да                   | Нет   |
| Публиковать от имени школы             | Да                      | Да                            | Нет                  | Нет   |
| Изменить чужой пост                    | Нет                     | Нет                           | Нет                  | Нет   |
| Назначить/отозвать роль учителя        | Да                      | Нет                           | Нет                  | Нет   |
| Создать класс                          | Да                      | Да                            | Нет                  | Нет   |
| Добавить ученика в класс               | Любой класс своей школы | Только свой класс             | Нет                  | Нет   |
| Читать/писать в школьный чат           | Своей школы             | Своей школы                   | Своей школы          | Нет   |
| Читать/писать в классный чат           | Классы своей школы      | Свой класс или явное членство | Только своё членство | Нет   |

Роль определяется на сервере для каждой школы отдельно. Публичный ID — идентификатор поиска, не пароль и не доказательство прав. Знание URL чата не даёт доступа. Отзыв роли учителя прекращает его административные права; удаление из школы удаляет членства в классах и закрывает её чаты. Удаление только из класса сохраняет членство в школе.

## Стек и почему он выбран

- **React 19 + TypeScript** — компонентный интерфейс, строгая проверка типов, общий язык клиента и сервера.
- **Vinext / Next App Router** — файловые маршруты и серверные обработчики, совместимые с Cloudflare Workers. Vinext выбран для доступного полноценного размещения UI и API в одном приложении; это осознанная зависимость от ещё молодого инструмента.
- **Cloudflare D1 (SQLite)** — настоящая реляционная база: участники, роли и связи классов удобно выражаются внешними ключами и SQL.
- **Drizzle Kit** — версионируемые миграции схемы. Запросы выполняются параметризованными prepared statements D1.
- **Cloudflare R2** — изображения отдельно от базы. Загрузка и выдача выполняются серверными маршрутами.
- **Shadcn/Radix, Lucide, next-themes, Sonner** — диалоги с управлением фокусом, вкладки, боковое меню, иконки, тема и уведомления.
- **Sites** — размещение Worker, базы и файлов с поддерживаемым входом ChatGPT. Нет хранения паролей в приложении.

## Процесс проектирования и разработки

Сначала была выделена базовая цепочка: школа → подтверждённый учитель → его класс → ученик. Личная лента осталась общей, а закрытое общение получило отдельную модель доступа. Схема данных создана до интерфейса: это позволило не свести роли к визуальному скрытию кнопок.

Затем реализованы серверные операции, компонентная оболочка и основные страницы. Интерфейс построен вокруг чтения и публикации: лента сразу доступна, школьные достижения выделяются отдельной карточкой, управление участниками вынесено в диалоги. Последний этап — проверка готового Worker разными пользователями и ручная проверка UI, включая мобильный экран.

Разработка выполнена с помощью Codex: генерация и редактирование кода, запуск проверок, анализ ошибок и подготовка документации. Это самостоятельный учебный MVP, а не готовая система для реального школьного внедрения.

## Подходы и методологии

- **Проверка прав на границе операции:** сервер заново проверяет школу, роль и принадлежность класса для каждого чтения и изменения чата.
- **Публичное и закрытое разделены в данных:** посты школы доступны всем; списки участников и чаты защищены членством и ролью.
- **Доступ отзывается сразу:** права не кэшируются в токене клиента; отозванная роль отражается в следующих запросах.
- **Сохранение при ошибках:** редакторы очищаются только после успешного ответа; повторная попытка не требует вводить текст заново.
- **Параметризованный SQL и транзакционные batch-операции:** создание школы с ролью владельца и чатом, а также добавление в класс выполняются согласованно.
- **Нормализованный поиск:** отдельное поле текста в нижнем регистре обеспечивает поиск кириллицы, который стандартный SQLite `lower()` сам по себе не обеспечивает.
- **Прогрессивное улучшение:** тема хранится локально как предпочтение, все предметные данные — на сервере. Доступен экспериментальный WebMCP-инструмент поиска при поддержке браузером.

## Компромиссы

- Вход через ChatGPT вместо собственной пары логин/пароль. Это уменьшает объём и риски хранения учётных данных, но требует аккаунта ChatGPT и платформенного шлюза Sites.
- Чат использует опрос раз в 5 секунд, а не WebSocket. Для MVP проще развернуть и отладить; нет мгновенных push-уведомлений и статуса «печатает».
- Один ответственный учитель на класс. Администратор видит все классы своей школы; учителя — свои и те, куда они явно добавлены.
- Одна фотография на публикацию, до 3 МБ, JPG/PNG/WebP. Грамота — публикация типа «Достижение» с фотографией документа; отдельного документооборота нет.
- Обработчики API собраны в одном предметном модуле. При росте приложения их следует разделить по ресурсам и ввести более строгие типы всех ответов.

## Известные ограничения

- Не проверяется юридическое право пользователя представлять школу. Администратор — создатель организации, учитель подтверждается этим администратором внутри приложения. Для реального запуска нужна верификация организаций.
- Нет модерации, жалоб, восстановления удалённых постов, передачи владения школой и самостоятельного удаления аккаунта.
- Нет сквозного шифрования: «закрытый чат» означает серверное ограничение доступа участниками, а не E2EE.
- Последние 100 сообщений загружаются в чат; история сохраняется, но прокрутка к более старым сообщениям пока не реализована. Комментарии ограничены первыми 200, каталог школ — 100, список участников — 500.
- Пагинация ленты по offset может повторить карточку при одновременной публикации; для большой аудитории нужен курсор. Поиск использует `LIKE`, не полнотекстовый индекс.
- Неиспользованные загрузки пока не очищаются из R2, метаданные EXIF не удаляются. Проверяется сигнатура формата и размер, но не выполняется серверное перекодирование изображения.
- Есть ограничение частоты сообщений, но нет комплексных антиспам-квот, CAPTCHA и системы резервного восстановления. Это обязательные дальнейшие работы перед эксплуатацией с настоящими учениками.
- На другом хостинге нельзя доверять входящим `oai-authenticated-user-*` от посетителей: нужен собственный доверенный auth-шлюз. В опубликованной версии их устанавливает Sites. Локальный mock никогда не должен быть доступен из интернета.

## API

Все пути ниже начинаются с `/api`. Изменения принимают JSON, кроме сырого файла в `POST /upload`. API возвращает понятную ошибку и статус 400/401/403/404/413/415/429/503.

| Маршрут                                       | Назначение                                  |
| --------------------------------------------- | ------------------------------------------- |
| `GET /session`, `PATCH /profile`              | Сессия, создание и изменение своего профиля |
| `GET/POST /schools`, `GET/PATCH /schools/:id` | Школы                                       |
| `GET/POST/DELETE /schools/:id/members`        | Участники и роли                            |
| `GET/POST /channels`                          | Доступные чаты и создание класса            |
| `GET/POST/DELETE /channels/:id/members`       | Состав класса                               |
| `GET/POST /channels/:id/messages`             | Сообщения закрытого чата                    |
| `GET/POST /posts`, `PATCH/DELETE /posts/:id`  | Публикации                                  |
| `POST/DELETE /posts/:id/like`                 | Идемпотентные лайки                         |
| `GET/POST /posts/:id/comments`                | Комментарии                                 |
| `GET /profiles/:publicId`                     | Публичный профиль                           |
| `GET/PATCH /notifications`                    | Уведомления и отметка прочтения             |
| `POST /upload`, `GET /media/:id`              | Загрузка и выдача изображения               |
| `GET /health`                                 | Проверка доступности базы                   |

## Размещение

Продакшен использует логические привязки `DB` (D1) и `BUCKET` (R2) в `.openai/hosting.json`. Sites создаёт реальные ресурсы и применяет миграции перед публикацией. Секреты и локальные данные не входят в Git. В репозитории сохранён идентификатор данного Site; при создании собственной копии на Sites необходимо зарегистрировать отдельный Site и заменить только его `project_id`, не использовать существующий чужой проект.

Репозиторий содержит исходники и lockfile; ZIP для сдачи не требуется. Форма сдачи не отправлялась автоматически.
